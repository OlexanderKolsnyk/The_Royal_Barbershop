# Оновлення системи

1. Редагуйте джерела, а не копії в docs/.
2. Запустіть node scripts/check.mjs. Якщо тести не пройшли — не публікуйте.
3. Якщо змінено сервер Google, скопіюйте generated/AppsScript.gs у чинний проєкт Apps Script. Оновіть чинне Web App розгортання новою версією. Збережіть URL, власника та доступи розгортання.
4. Збережіть джерела у GitHub; Pages публікує main, папку /docs.
5. Опублікуйте відповідну версію Sites його штатним процесом. Не змінюйте project_id у .openai/hosting.json.
6. Перевірте каталог, вільний час і форму входу. Фіктивні записи — лише в окремій тестовій таблиці.

Google Script Properties: SPREADSHEET_ID, GATEWAY_SECRET, OWNER_EMAIL, BACKUP_FOLDER_ID. OWNER_EMAIL визначає внутрішній запис власника; це не вимога входу через email. ADMIN_PASSWORD_* не змінюйте під час звичайного оновлення.

Sites runtime: GAS_URL, GATEWAY_SECRET, PUBLIC_ORIGIN. Секрети не зберігаються у frontend, GitHub або архівах джерел. Таблиця та резервні копії залишаються приватними. Звичайне оновлення не потребує повторної ініціалізації бази чи зміни пароля.

Відкат коду: попередній GitHub-коміт і відповідні версії Sites/Apps Script. Він не відновлює дані. Резервну копію спочатку перевіряйте в окремій приватній таблиці; не замінюйте робочу без рішення власника.
