# Розгортання

## 1. Приватна база

Створіть або імпортуйте Google-таблицю з вкладками з `RoyalCore.TABLES`. `initialize()` також створює відсутні вкладки. Доступ до таблиці та резервних копій залиште лише власнику; працівникам доступ до Drive не потрібен. Не публікуйте таблицю у вебі.

## 2. Google Apps Script

Скопіюйте `Core.gs`, `Initial.gs`, `Api.gs`; або об’єднайте їх у такому порядку в один файл. Увімкніть показ маніфесту та вставте `appsscript.json`. У Script Properties задайте:

| Властивість | Значення |
|---|---|
| SPREADSHEET_ID | ID приватної таблиці |
| GATEWAY_SECRET | 32 випадкових байти або більше, лише на сервері |
| OWNER_EMAIL | Email ChatGPT-акаунта власника адмінпанелі |
| BACKUP_FOLDER_ID | ID приватної папки резервних копій |

Виконайте `initialize`, перегляньте запит Google на доступ до таблиць, Drive й тригерів. Авторизацію нового скрипту власник виконує сам. `initialize` не замінює наявні бізнес-дані; початковий каталог додає лише якщо Services порожня. Далі виконайте `installMaintenance` для щоденної резервної копії й очищення аналітики, технічних логів та застарілих ключів повтору.

Опублікуйте версійний Web App: виконання від імені власника, доступ до endpoint для anyone. Усі запити все одно перевіряються за HMAC, часом і nonce; без секрету операції не виконуються. Зміна публічності серверного endpoint потребує окремого погодження власника. Скопіюйте `/exec` URL лише у runtime-параметри шлюзу. Не публікуйте секрет у коді.

## 3. Шлюз

Поточний проєкт підтримує Cloudflare Worker через Sites. У runtime задайте `GAS_URL` (Web App `/exec`), `GATEWAY_SECRET` (той самий серверний секрет), `PUBLIC_ORIGIN` (`https://olexanderkolsnyk.github.io`). Позначте секрети як secret. Розгорніть зібраний `dist/server/index.js`. Хостинг повинен встановлювати перевірені заголовки `oai-authenticated-user-email`; не переносіть цей код на звичайний Worker без заміни довіреного механізму авторизації. Ніколи не довіряйте такому заголовку від безпосереднього клієнта.

`/health` показує лише факт наявності конфігурації, не доводить доступність Google. Перевірте `/api` діями catalogue, slots і через окрему тестову базу — book/bookingChange/payment.

## 4. GitHub Pages

У репозиторії увімкніть Pages: Deploy from a branch → main → `/docs`. Файли публічного `web/` копіюються в репозиторій до `docs/` окремо від документації (технічна документація лишається у `documentation/`). `.nojekyll` потрібен для статичної публікації. Альтернатива — GitHub Actions з артефактом `web/`.

Перевірте `web/config.js`: API має вказувати на ваш розгорнутий шлюз, ADMIN — на `/admin` того самого шлюзу. Не задавайте GAS_URL чи секрет у frontend. Якщо API недоступний, каталог показує початкові надані ціни, а онлайн-запис закривається; немає імітації збереження.

## 5. Перед відкриттям запису

Увійдіть у `/admin` через ChatGPT-акаунт власника. Перевірте початкові тривалості й назву майстра; задайте реальні відсотки; переконайтеся, що 08:00–20:00 є чинним графіком. Після перевірки на окремій тестовій таблиці увімкніть «Онлайн-запис» у налаштуваннях. Не тестуйте фіктивні візити в робочій базі.
