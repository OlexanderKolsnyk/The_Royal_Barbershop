# Практичні межі та перевірки

Поточні тести запускаються командою node scripts/check.mjs, яка також збирає сайт. Вони охоплюють конфлікти записів, погоджені ціни, парольні сесії, часові пояси, вибіркові читання та початкову прокрутку. Це не незалежний аудит безпеки чи навантажувальне випробування.

Читання: каталог — 4 вкладки; слоти — 7; вхід — Users; власний запис — Bookings. Аналітика не читає всю базу перед записом подій. Мутації та адміндані зберігають повний свіжий знімок під ScriptLock.

Слоти все ще читають історію Bookings цілком. Це рішення для невеликого барбершопу; за значного росту знадобляться архівування або інша операційна база.

- Один пароль дає повний доступ власника; окремі ролі працівників у цьому режимі не застосовуються.
- Серверна сесія триває до години, може завершитися раніше через очищення кешу. Після п’яти помилок діє тимчасове блокування джерела спроб.
- Telegram — посилання на чат; автоматичні нагадування не підключені.
- Google і хостинг мають квоти та можуть бути недоступні; гарантії вічної роботи немає.
- Копії залежать від установленого та працездатного dailyMaintenance. Код резервування не доводить успішність останньої копії; відновлення перевіряється окремо в тестовій таблиці.
- Аудит допомагає виявляти зміни, але власник Drive технічно може редагувати таблицю. Звичайні зміни робіть через адмінку.
